# 润墨 API（降 AI 模块）

本文件是 `gzh-creation-system` 的润墨降 AI 模块说明，随本 skill 一起分发。脚本在本 skill 的 `scripts/runmo.py`，只用 Python 标准库，不需要装任何第三方包。

这一步只做一件事，把降AI前稿的正文交给润墨的深度优化 3.0 重写一遍，降低 AI 味，产出降AI后稿。它返回什么正文，就用什么正文，不核对、不修复、不补句、不再次润色。内容好不好由用户自己看。

**润墨之后直接进入排版，不做逐字比对、原创度、查重或相似度检查。** 唯一的检查是排版后对发布稿做一次朱雀 AI 率检测（见 `朱雀检测API.md`），它只报告，不拿结果改润墨返回的正文。

## 一、何时执行

**条件步骤**，满足两个条件才跑：

- 本 skill 的 `scripts/runmo.py` 存在且能调用
- 密钥可用（工作区 `工具/runmo.key` 或环境变量 `RUNMO_API_KEY`）

任一不满足就一句话说明并跳过，**不中断流程**，其余步骤照常。发给别人的包里没有密钥，对方那边会自动跳过这一步。

执行时机固定在标题点选之后，不要提前跑。

## 二、密钥

密钥是明文，单独安全配置，**绝不写进本文件、SKILL.md、脚本或任何分享包**。

读取优先级（脚本自动处理）：

1. 命令行 `-k`
2. 环境变量 `RUNMO_API_KEY`
3. 工作区文件 `工具/runmo.key`（一行纯文本，52 字节左右）

调用命令里不要带密钥，日志和回复里也不要出现密钥。密钥外泄就去润墨网页「账户 → API 访问」撤销重发，替换密钥文件内容即可。

## 三、调用命令

```bash
python "{技能安装目录}/scripts/runmo.py" "<降AI前稿绝对路径>" -m deep3 --body-only -o "<成品目录>/<文章名>-降AI后.md"
```

- `-m deep3`，深度优化 3.0，当前工作流默认用这个模式（2026-10-03 起，脚本默认值也已改成 `deep3`，省略 `-m` 是同一模式）。失败先重试一次；仍失败改用 `-m deep`（深度优化 2.0）跑一次兜底，并在交付里注明用了 2.0；再失败就如实报错并跳过这一步，不中断流程。
- `--body-only`，首行是 `# 标题` 时不提交它，只提交正文，结果自动把标题原样拼回
- `--keep-tail` 已停用：2026-10-24 起文章结尾不留互动钩子，不需要尾部保护。任何情况都不传；传了会把钩子原样拼回，与「结尾不留钩子」冲突。参数仍保留在脚本里仅为兼容
- `-o` 指定输出路径，落到 `成品/待发布/YYYY-MM-DD/<文章名>-降AI后.md`（正常由 `scripts/pipeline.py` 代为调用）
- 原降AI前稿保留不动，作留底

其他可用参数：`--text "一段文字"` 直接处理文本并打印，`--check req_xxxx` 查询既有任务结果。

## 四、接口本身（脚本已封装，备查）

| 项 | 值 |
|---|---|
| Base URL | `https://www.runmo.art/api/v1` |
| 认证 | `Authorization: Bearer rm_live_xxx` |
| 处理接口 | `POST /rewrite` |
| 查询接口 | `GET /jobs/{request_id}` |
| 返回方式 | 异步任务，先拿任务号再轮询 |
| 幂等键 | 必填请求头 `Idempotency-Key`，每次一个唯一 UUID，不带会报 400 |

状态流转：`pending` → `processing` → `completed`，失败是 `failed`，结果在 `text` 字段。

五种模式：`layout`（轻度排版）、`quick_narrative`（快速 · 叙事）、`quick_explanatory`（快速 · 说明）、`deep`（深度优化 2.0，兜底与重跑用）、`deep3`（深度优化 3.0，脚本默认）。

## 五、失败处理

- 提交报 400，先查 `Idempotency-Key` 是否存在
- 提交 401 或 403，密钥无效或额度用尽，一句话报给用户，跳过这一步，不反复重试
- 轮询超时（脚本上限 900 秒）或返回 `failed`：先用 `deep3` 重试一次；仍失败改用 `-m deep`（2.0）兜底一次；再失败才报「润墨未完成，保留降AI前稿」，以降AI前稿进入排版。重试前先用 `--check` 确认原任务确实没出结果，避免重复计费
- 中断后重新接手时，先用 `--check req_xxxx` 查询既有任务号，**已提交的任务不重复提交**，避免重复计费

## 六、两个固定事实

**润墨的路子是啰嗦化。** 它会把精练的句子展开、绕圈、口语化，这是它降 AI 的原理。代价是文章变长、节奏变慢。它的风格方向（长句、多连词）与 human-writing 的（短句、少连词）相反，所以只能放在最后一步，之后不再改文风。

**它可能吞掉短结构元素。** 实测（deep3，595 字正文，16 秒）它会丢掉段落小标题、结尾互动句这类短句，并把段落揉成很长的整块。**段落小标题不补回**，排版只做分段、留白和加粗，任何被吞的句子都不补回。

## 七、与工作区脚本的关系

工作区 `工具/runmo.py` 是同一份脚本的实例，两处内容应保持一致。若不一致，以本 skill 自带的 `scripts/runmo.py` 为准。密钥只存在工作区，不随 skill 分发。
